# CRM Telegram-бот — навигация: поиск-карточки, списки заездов, заезд от админа: спецификация

Дата: 2026-10-02
Статус: на ревью
Дополняет: `docs/superpowers/specs/2026-09-19-crm-bot-design.md`,
`docs/superpowers/specs/2026-09-23-crm-bot-gaps-design.md`

## Контекст

После ручной проверки бота выяснилось, что пользоваться им каждый день нельзя:
заезд можно только **создать**, но не найти потом. Конкретно (сверено с кодом
на `main` 3a409c9):

1. **Поиск — тупик.** `bot/handlers/search.py` выводит результаты простым текстом,
   без кнопок; открыть клиента/авто нельзя. Исходный спек обещал
   «текст → карточки клиент+авто».
2. **К существующему заезду не вернуться.** Карточка заезда отправляется только при
   создании (`bot/handlers/visits.py: send_visit_card`). В API нет списка заездов —
   только `GET /visits/{id}`.
3. **ADMIN не может завести заезд.** Исходный спек: «ADMIN — всё, что MASTER». В коде
   кнопка «Новый заезд» только у MASTER (`bot/keyboards.py`), т.к. `assigned_master_id`
   обязан ссылаться на MASTER, а шага «выбор мастера» (он есть в исходном спеке) нет.
4. **`/new_client`, `/new_vehicle` не видны** — нет в меню, бот не регистрирует
   команды в Telegram.
5. **Поиск у механика падает.** Текст от MECHANIC уходит в поиск, а
   `GET /clients/{id}` / `GET /vehicles/{id}` разрешены только ADMIN/MASTER →
   «Недостаточно прав».

Цель цикла: мастер/админ открывает бота и за 1–2 нажатия попадает к нужному текущему
заезду, либо находит клиента/машину и видит их историю; админ заводит заезды наравне
с мастером.

## Решения (согласованы)

- Вход к заезду — **оба пути**: кнопка «Заезды в работе» в меню + история заездов из
  карточки клиента/машины.
- «Заезды в работе» для MASTER — **все незакрытые заезды филиала, свои сверху**.
  ADMIN видит то же (для него «свои» — пустое множество, порядок по дате).
- Ответственный мастер при создании: **MASTER — он сам (шага нет), ADMIN — выбирает**
  из списка мастеров.
- API — **отдельные read-эндпоинты со сводками** (бот делает один запрос на экран;
  фильтры и сортировка в API, переиспользуются будущим Mini App).
- Включено дополнительно: **«Новый заезд» из карточки машины**; **явное
  предупреждение об обрезке списка**.

## Backend

Новые эндпоинты только читают данные; `VisitOut` получает дополнительные поля
(обратно совместимо). Схема БД не меняется, миграций нет.
Мягко удалённые записи (`deleted_at IS NOT NULL`) исключаются везде.

### `GET /visits`

Роли: ADMIN, MASTER (MECHANIC → 403).

Query-параметры (все необязательные, комбинируются через AND):

| Параметр | Смысл |
|---|---|
| `active=true` | статус не `issued` и не `cancelled` |
| `client_id=<uuid>` | заезды клиента |
| `vehicle_id=<uuid>` | заезды машины |

Ответ — `VisitListOut`:

```json
{
  "items": [
    {
      "id": "uuid",
      "status": "in_progress",
      "created_at": "2026-10-02T10:15:00+03:00",
      "client_id": "uuid",
      "client_name": "Иванов Пётр",
      "vehicle_id": "uuid",
      "plate_number": "А123ВС77",
      "make_model": "Toyota Camry",
      "assigned_master_id": "uuid",
      "master_name": "Петров"
    }
  ],
  "has_more": false
}
```

- Сортировка: сначала `assigned_master_id == acting_user.id`, затем `created_at DESC`.
- Лимит 30 (константа в сервисе). Запрос берёт 31 строку; если пришла 31-я —
  `has_more=true`, она отбрасывается.
- Сводка собирается одним SQL-запросом с JOIN на `clients`, `vehicles`, `users`
  (без N+1).
- Реализация: метод `VisitService.list_visits(acting_user, active, client_id,
  vehicle_id)` + репозиторий; роут в `app/modules/visits/router.py`
  (`GET ""` — до `GET /{visit_id}`).

### `GET /clients/{client_id}/vehicles`

Роли: ADMIN, MASTER. Текущие машины клиента: `vehicle_ownership.date_to IS NULL`,
машина не удалена. Ответ — `list[VehicleOut]`, порядок по `plate_number`.
404, если клиента нет.

### `GET /vehicles/{vehicle_id}/owner`

Роли: ADMIN, MASTER. Текущий владелец (`date_to IS NULL`) — `ClientOut`.
404, если машины нет; `null` (200), если текущего владельца нет.

### `GET /users/masters`

Роли: ADMIN. Активные пользователи с ролью MASTER, сортировка по `full_name`.
Устроен как существующий `GET /users/mechanics` (`UserService.list_masters`).
Роут объявляется до `GET /users/{...}`-маршрутов с параметрами.

## Бот

### Главное меню (`bot/keyboards.py`)

| Роль | Кнопки |
|---|---|
| MASTER | Новый заезд, **Заезды в работе**, Поиск, Регистрация клиента (бумага) |
| ADMIN | Новый заезд, **Заезды в работе**, Поиск, Регистрация клиента (бумага), Добавить сотрудника |
| MECHANIC | Мои работы (без изменений) |

`MASTER_ONLY_BUTTONS` и комментарий про невозможность ADMIN выбрать мастера
удаляются; новая кнопка регистрируется в `bot/handlers/menu.py`.

### Русские названия статусов

Новый модуль `bot/visit_status.py` (по образцу `bot/work_item_status.py`):
словарь `VISIT_STATUS_LABELS`:

| API | Бот |
|---|---|
| received | Принят |
| diagnostics | Диагностика |
| approval | Согласование |
| in_progress | Ремонт |
| waiting_parts | Ждём запчасти |
| ready | Готов |
| issued | Выдан |
| cancelled | Отменён |

Используется в списках, шапке карточки и на кнопках смены статуса
(`callback_data` по-прежнему содержит код статуса).

### Экран «Заезды в работе»

`GET /visits?active=true`. Сообщение `Заезды в работе (N)` + по inline-кнопке на заезд:

```
[⭐ А123ВС77 · Иванов Пётр · Ремонт]
[В001ОР50 · Петрова Анна · Диагностика]
```

- `⭐` — `assigned_master_id == user.id`.
- Пусто → «Незакрытых заездов нет».
- `has_more` → последняя строка текста «Показаны последние 30».
- Кнопка → `visit_open:<encode_id(visit_id)>` → карточка заезда.

### Поиск (`bot/handlers/search.py`)

Результаты — inline-кнопки вместо текста:

```
Найдено: 2
[👤 Иванов Пётр — +7 999 123-45-67]
[🚗 Toyota Camry (А123ВС77)]
```

`client_open:<id>` / `vehicle_open:<id>`. Пусто → «Ничего не найдено.»
(как сейчас). `/search` лимита не имеет, поэтому бот показывает первые 10
результатов; если их больше — строка «Показаны первые 10 — уточните запрос».
Подписи кнопок собираются через существующие `get_client`/`get_vehicle` на
каждый показанный результат (≤ 10 запросов; переделка `/search` на сводки —
вне рамок).

**MECHANIC:** текст не уходит в поиск; ответ «Поиск доступен мастерам и
администраторам. Ваши задачи — в «Мои работы».» (вместо текущей ошибки 403).

### Карточка клиента

```
👤 Иванов Пётр
+7 999 123-45-67
[🚗 Toyota Camry (А123ВС77)]      ← vehicle_open, по машине из GET /clients/{id}/vehicles
[📋 Заезды клиента]               ← visits_by_client:<id>
```

### Карточка машины

```
🚗 Toyota Camry · А123ВС77
VIN: JTNB… · Пробег: 84 500 км
[👤 Владелец: Иванов Пётр]        ← client_open; кнопки нет, если владельца нет
[📋 Заезды по машине]             ← visits_by_vehicle:<id>
[➕ Новый заезд]                  ← new_visit_for:<vehicle_id>; только если есть владелец
```

### История заездов

`GET /visits?client_id=…` / `?vehicle_id=…` (все статусы). Формат как у
«Заездов в работе», в начале кнопки дата: `[02.10 · А123ВС77 · Ремонт]`. Пусто →
«Заездов ещё не было». `has_more` → «Показаны последние 30».

### Карточка заезда (`send_visit_card`)

Шапка вместо `Заезд <uuid>`:

```
А123ВС77 · Toyota Camry · Иванов Пётр
Статус: Ремонт · Мастер: Петров
Сумма: 12 400
```

Шапка строится из одного `GET /visits/{id}`: `VisitOut` расширяется полями
сводки `client_id`, `vehicle_id`, `assigned_master_id`, `client_name`,
`plate_number`, `make_model`, `master_name` (те же, что у элемента
`GET /visits`; `POST /visits` и `PATCH /visits/{id}/status` возвращают
тот же расширенный `VisitOut`). Работы и кнопки — без изменений, кроме русских
статусов.

### Визард «Новый заезд»

- **MASTER** — без изменений (`assigned_master_id = user.id`).
- **ADMIN** — после пробега (и подтверждения пробега, если оно было) состояние
  `NewVisitStates.choosing_master`: `GET /users/masters` → кнопки
  `master_pick:<encode_id>`; выбор → `POST /visits`.
  Мастеров нет → «Сначала добавьте мастера через «Добавить сотрудника».»,
  state очищается.
- **Из карточки машины** (`new_visit_for:<vehicle_id>`, ADMIN/MASTER): бот берёт
  владельца (`GET /vehicles/{id}/owner`), кладёт `client_id`/`vehicle_id` в FSM и
  сразу просит пробег; дальше общий путь (подтверждение пробега, выбор мастера
  для ADMIN). Владельца нет → «У машины нет владельца — заведите заезд через
  «Новый заезд».»

### Команды Telegram

В `bot/main.py` после `create_bot` — `bot.set_my_commands([...])`:

| Команда | Описание |
|---|---|
| `/start` | Главное меню |
| `/cancel` | Отменить текущее действие |
| `/new_client` | Новый клиент |
| `/new_vehicle` | Новая машина |

Один общий список (без scope по ролям). Ошибка `set_my_commands` логируется
и не мешает старту.

### Callback-данные

Все новые callback'и используют `encode_id` (22 символа на UUID), длина ≤ 64 байт.
Новые префиксы: `visit_open`, `client_open`, `vehicle_open`, `visits_by_client`,
`visits_by_vehicle`, `new_visit_for`, `master_pick`.

## Ошибки

- Ошибки API → существующий `ErrorHandlingMiddleware` (404 → «Не найдено»,
  403 → «Недостаточно прав» и т.д.).
- Кнопки из старых сообщений: новые callback-хендлеры не зависят от FSM-state
  (кроме `master_pick`), поэтому работают и через день; если сущность удалена —
  404 → «Не найдено».
- `master_pick` вне state `choosing_master` ловит существующий `fallback`.

## Тестирование

**API** (`tests/modules/...`, ASGI-шаблон с `X-User-Id`):

- `GET /visits`: свои сверху; `active` исключает issued/cancelled; фильтры
  `client_id`/`vehicle_id`; удалённые заезды/клиенты/машины не попадают;
  `has_more` при 31 записи; поля сводки; MECHANIC → 403.
- `GET /clients/{id}/vehicles`: только текущие владения; удалённые машины
  исключены; 404 на несуществующего клиента.
- `GET /vehicles/{id}/owner`: текущий владелец; `null` без владельца; 404.
- `GET /users/masters`: только активные MASTER, по имени; MASTER → 403.
- `GET /visits/{id}`, `POST /visits`, `PATCH /visits/{id}/status`: новые поля сводки.

**Бот** (`tests/bot/...`, по шаблону существующих тестов хендлеров с моком
`ApiClient`):

- меню ADMIN/MASTER/MECHANIC;
- «Заезды в работе»: ⭐ у своих, пустой список, «Показаны последние 30»;
- поиск: кнопки клиента/авто, пусто, обрезка до 10, MECHANIC получает подсказку без вызова API;
- карточка клиента и машины: кнопки, отсутствие владельца;
- история заездов клиента/машины;
- шапка карточки заезда и русские статусы на кнопках;
- визард ADMIN: шаг выбора мастера, нет мастеров;
- визард из карточки машины: старт с пробега, ветка без владельца;
- регистрация команд (`set_my_commands` вызван со списком; ошибка не роняет старт).

## Вне рамок (следующие шаги)

- **Редактирование клиента/машины** — PATCH-эндпоинты, уникальность
  телефона/VIN, аудит, визарды правки. Отдельный цикл.
- **Смена ответственного мастера заезда** — сначала бизнес-правила: кто может,
  уведомлять ли старого/нового мастера.
- **Пагинация** списков («Показать ещё») — пока лимит 30 с явным предупреждением.
- Переделка `/search` на ответ-сводку (сейчас бот добирает подписи по id).
- Команды Telegram с разными списками по ролям (`BotCommandScopeChat`).
