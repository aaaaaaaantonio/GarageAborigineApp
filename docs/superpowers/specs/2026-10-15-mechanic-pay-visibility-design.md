# Заработок механиков и настройки видимости — дизайн

Дата: 2026-10-15. Решения владельца приняты в диалоге 2026-10-15 (см. «Решения»).

## Цель

Механик видит, сколько стоят работы и запчасти в заездах, где он работает, видит свой
заработок (заработано и ожидается) и график заработка в «Статистике». Админ одной
настройкой включает или выключает это для всех механиков и отдельно решает, показывать
ли механикам имя клиента, телефон клиента и VIN. Админ задаёт каждому механику схему
оплаты.

Успех: при включённых настройках механик открывает карточку своего заезда и видит то же,
что админ (кроме выключенных полей), а в «Статистике» — «Заработано» и «Ожидается» в ₽.
При выключенных — механик видит ровно то, что видит сегодня.

## Решения

| Вопрос | Решение |
|---|---|
| Схема оплаты | У каждого механика одна из трёх: процент от стоимости работы, фикс за нормо-час, вся стоимость работы. |
| Когда заработано | «Заработано» — свои работы в выданных заездах. «Ожидается» — свои работы в открытых заездах. |
| Что в карточке | Весь заезд, где у механика есть хотя бы одна работа: все работы и запчасти, итог. Заработок — только со своих работ. |
| Переключатели | Общие для всех механиков: цены и заработок; телефон клиента; имя клиента; VIN / номер кузова. |
| По умолчанию | Все четыре выключены — механики видят то же, что до этой фичи. |
| Админы-исполнители | Схема оплаты и заработок — только у роли «механик». Админ видит всё и так. |

## Модель данных (одна миграция)

**`app_settings`** — новая таблица «ключ → значение»:
`key String(64) PK`, `value JSON NOT NULL`, `updated_at timestamptz`, `updated_by_user_id UUID NULL`.
Отсутствующий ключ = значение по умолчанию из кода. Ключи этой фичи (все `bool`, по
умолчанию `false`):

| Ключ | Что открывает механику |
|---|---|
| `mechanic_sees_prices` | Ставки, суммы работ и запчастей, скидку, итог заезда, свой заработок, ₽ в «Статистике». |
| `mechanic_sees_client_name` | Имя клиента / название организации. |
| `mechanic_sees_client_phone` | Телефон и Telegram-username клиента. |
| `mechanic_sees_vin` | VIN / номер кузова. |

**`users`** — две колонки: `pay_scheme` (enum `percent | per_hour | full`, NULL = не задана),
`pay_value Numeric(10,2) NULL`. Правила: `percent` — 0 < value ≤ 100; `per_hour` —
value > 0 (₽ за нормо-час); `full` — value NULL.

**`visit_work_items`** — колонка `mechanic_pay Numeric(10,2) NULL`: заработок механика с
этой работы, зафиксированный при выдаче машины.

## Расчёт заработка

Стоимость работы = `norm_hours × hourly_rate` (до скидки; скидка заезда на заработок не
влияет). Запчасти в заработок не входят.

| Схема | Заработок с работы |
|---|---|
| `percent` | стоимость × value / 100 |
| `per_hour` | norm_hours × value |
| `full` | стоимость |
| не задана | нет (`null`) |

Округление до копеек (`Decimal`, `ROUND_HALF_UP`). Одна чистая функция
`work_pay(norm_hours, hourly_rate, scheme, value) -> Decimal | None` в новом модуле
`app/modules/pay/`, её используют и снимок, и «ожидается».

**Снимок при выдаче.** В `VisitService.change_status` при переходе в `ISSUED`: для каждой
работы заезда, чей исполнитель — пользователь с ролью `mechanic` и заданной схемой,
записать `mechanic_pay = work_pay(...)` по текущей схеме. Работы без исполнителя, с
исполнителем-админом или без схемы получают `NULL`. Выданный заезд конечен
(`ISSUED` без исходящих переходов), поэтому снимок не меняется.

**Заработано** за окно = сумма по своим работам выданных в окне заездов (момент — как в
статистике: последний переход в `issued`): `mechanic_pay`, а если снимка нет (заезд выдан
до фичи или до того, как схема была задана) — `work_pay` по текущей схеме. Если у
механика схема не задана и снимков нет — «—».

**Ожидается** = сумма `work_pay` по текущей схеме для своих работ в открытых заездах
(статус не `issued` и не `cancelled`, заезд не удалён), кроме доп. работ, которые клиент
ещё не согласовал (`is_extra_work and not approved_by_client`). Без периода — это
текущее состояние.

## API

Все ограничения на сервере: выключенное поле в ответ механику не попадает (`null`), а не
прячется в интерфейсе.

**Настройки**
- `GET /settings` — все роли персонала: `{mechanic_sees_prices, mechanic_sees_client_name,
  mechanic_sees_client_phone, mechanic_sees_vin}` (булевы, не секрет; клиенту нужны, чтобы
  не рисовать пустые блоки).
- `PATCH /settings` — только админ; частичное обновление тех же полей; запись в
  `audit_log` (`entity_type="settings"`, `entity_id` = нулевой UUID, old/new значения).
- `GET /settings/pay` — только админ: активные механики `[{user_id, full_name, pay_scheme,
  pay_value}]`.
- `PATCH /settings/pay/{user_id}` — только админ: `{pay_scheme, pay_value}`; 422 при
  нарушении правил выше или если пользователь не активный механик; запись в `audit_log`
  (`entity_type="user"`, `action="pay_changed"`). Схема не попадает в `UserOut`, чтобы её
  не видели мастера через `/users/mechanics`.

**Карточка заезда для механика**
- `GET /visits/{visit_id}/mechanic-view` — только механик; 404, если заезда нет или он
  удалён; 403, если у механика нет ни одной работы в этом заезде (любой статус заезда,
  включая выданные и отменённые — для «Выполненных»).
- Ответ: `id, status, created_at, mileage_at_intake, plate_number, make_model, master_name,
  client_name?, client_phone?, client_telegram_username?, vin?, discount?, total_amount?,
  my_pay_total?, works[]`. Работа: `id, name, category, status, mechanic_name, is_mine,
  norm_hours, hourly_rate?, amount?, my_pay?, parts[]`. Запчасть: `name, article_number,
  quantity, availability_status, unit_price?, amount?`. Поле с `?` — `null`, когда
  соответствующая настройка выключена. `my_pay` — только у своих работ: снимок, иначе
  `work_pay` по текущей схеме; `null`, если схема не задана. `my_pay_total` — сумма своих
  `my_pay` в этом заезде.

**Статистика**
- `/stats/mine` для механика при `mechanic_sees_prices = true` добавляет KPI
  `earned` «Заработано» (`rub`, с дельтой к прошлому окну; «—» и `text`, если считать не из
  чего), `expected` «Ожидается» (`rub`, `compare=False`) и график `earned` «Заработок»
  (`bars`, `rub`, по шагам окна). При `false` ответ как сейчас — без единого `rub`.

## Веб

- **«Ещё» → «Настройки»** (`/settings`, только админ):
  - блок «Что видят механики» — четыре переключателя, сохраняются сразу (тост «Сохранено»);
  - блок «Оплата механиков» — строка на механика: имя, выбор схемы (`Picker`: «Не задана»,
    «Процент от работы», «Фикс за нормо-час», «Вся стоимость»), поле числа (скрыто для
    «Вся стоимость» и «Не задана»; подпись «%» или «₽ за н/ч»), кнопка «Сохранить».
- **Карточка заезда механика** (`/my/visit/:visitId`): открывается кнопкой «Карточка
  заезда» на экране работы механика и из «Выполненных». Только чтение: шапка (госномер,
  марка, пробег, мастер, статус; имя/телефон/VIN — если пришли), список работ с
  исполнителем, нормо-часами и (если цены включены) суммой и запчастями с ценами; свои
  работы отмечены «моя» и «ваш заработок N ₽» (или «схема оплаты не задана»); внизу итог,
  скидка и «Ваш заработок по заезду».
- **Экран работы механика**: при включённых ценах — блок «Стоимость работы», запчасти с
  ценами и «Ваш заработок» из того же `mechanic-view`.
- **«Статистика» механика**: новые KPI и график приходят с сервера; экран не меняется.

## Бот (паритет)

- **Механик**: на экране своей работы кнопка «🚗 Карточка заезда» → текстовый экран с тем
  же содержимым, что в вебе (поля по тем же настройкам). В «Статистике» новые KPI и
  график рисуются существующим кодом.
- **Админ**: пункт меню «⚙️ Настройки» → четыре кнопки-переключателя «✅/⬜ Цены и
  заработок» и т. д. (нажатие сразу меняет настройку) и кнопка «💰 Оплата механиков» →
  список механиков → выбор схемы → ввод числа (визард с шагом назад, как остальные).
  `callback_data` ≤ 64 байт.

## Тесты

- `work_pay` по трём схемам, «не задана», округление.
- Снимок при выдаче: записывается механику со схемой; `NULL` для админа-исполнителя и без
  схемы; не меняется после смены схемы.
- «Заработано»: снимок важнее текущей схемы; фолбэк на текущую схему без снимка.
- «Ожидается»: только открытые заезды, без несогласованных доп. работ.
- `mechanic-view`: 403 без своей работы; каждое `?`-поле `null` при выключенной настройке и
  заполнено при включённой; `my_pay` только у своих работ.
- Настройки: 403 для не-админа на `PATCH`; значения по умолчанию без строк в таблице;
  аудит пишется; 422 на неверную схему/значение.
- `/stats/mine` механика: без `rub` при выключенных ценах (старый тест остаётся), с
  `earned`/`expected` при включённых.
- Веб: экран настроек (переключатель шлёт `PATCH`), карточка механика с выключенными и
  включёнными ценами. Бот: экраны настроек и карточки, размер `callback_data`.

## Вне объёма

- Заработок мастера и админа, оклады, выплаты и отметки «выплачено».
- Индивидуальные настройки видимости для отдельного механика.
- Изменение схемы задним числом для уже выданных заездов (снимок не пересчитывается).
