# Фильтры и сортировки списков: спецификация

Дата: 2026-10-13. Ветка: `filters-sorting`. Затрагивает API, веб/Mini App и бота.

## Зачем

Списки работ и заездов растут: «Заезды в работе» обрезаются на 30, «Выполненные» на 100,
история работ на 30. Фильтры веба сейчас отбирают только уже загруженное, поэтому при
длинных списках они врут. Нужны фильтры и сортировки для каждой роли, на сервере, в вебе
и в боте одинаково (правило паритета UI ↔ бот).

## Решения

- **Фильтры и сортировки считаются на сервере** (параметры запроса). Клиенты только рисуют.
- **«Дата смены статуса»** (`status_changed_at`) = последний `visit_status_log.changed_at`
  заезда, а если записей нет — `visits.created_at`. Считается коррелированным подзапросом.
  Для закрытых заездов это дата закрытия (выдачи/отмены).
- **«Долго стоят»** = открытый заезд, статус не менялся `STALE_DAYS = 3` дня и больше.
- **Срочность работы** (порядок): В работе → Не начата → Ждёт запчасти → Готово.
- **Воронка заезда** (порядок): Принят → Диагностика → Согласование → Ремонт →
  Ждём запчасти → Готов → Выдан → Отменён.
- Периоды («Неделя / Месяц / Квартал / Всё») клиент переводит в `since` (ISO datetime,
  неделя = 7 дней, месяц = 30, квартал = 90). Сервер фильтрует `status_changed_at >= since`
  (для закрытых — по дате закрытия).
- Механик не видит денег: в его ответах только нормо-часы.
- Неизвестные значения фильтров → 422 (FastAPI/enum), пустые списки — нормальный ответ.

## API

### `GET /visits` (ADMIN, MASTER) — расширение

Новые необязательные параметры:

| Параметр | Тип | Смысл |
|---|---|---|
| `status` | `VisitStatus`, повторяемый | только эти статусы |
| `closed` | bool | только выданные и отменённые (архив) |
| `master_id` | uuid | ответственный мастер |
| `unassigned_work` | bool | есть хотя бы одна работа без механика |
| `stale` | bool | открыт и статус не менялся ≥ 3 дней |
| `since` | datetime | `status_changed_at >= since` |
| `sort` | `date` (по умолч.) / `stale` / `status` / `amount` | |
| `offset` | int ≥ 0 | для «Показать ещё» / страниц |

Сортировки: `date` — как сейчас (в общем списке свои заезды выше, затем новые сверху);
`stale` — `status_changed_at` по возрастанию (застрявшие сверху); `status` — по воронке,
внутри новые сверху; `amount` — сумма по убыванию.

Ответ `VisitOut` += `status_changed_at: datetime`. `VisitListOut` += `total_count: int`
(всего по фильтру, без лимита) и `issued_amount: float` (сумма выданных по фильтру, без
лимита). Лимит страницы прежний — 30.

### `GET /work-items/mine` (MECHANIC) — расширение

`status` (повторяемый `WorkItemStatus`), `sort` = `urgency` (по умолч.) | `car`.
`urgency`: по срочности, затем по дате заезда. `car`: работы одной машины подряд, машины
упорядочены по самой срочной работе, внутри машины — по срочности.

### `GET /work-items/mine/done` (MECHANIC) — изменение формата

Параметры: `since`, `outcome` = `issued` | `cancelled`. Ответ теперь объект:
`{items: [...], count: int, total_norm_hours: float, has_more: bool}`; элемент += `norm_hours`,
`closed_at` (дата выдачи/отмены). Порядок: `closed_at` по убыванию. Лимит 100.

### `GET /work-items/board` (ADMIN, MASTER) — новый «Доска работ»

Работы во всех открытых заездах. Параметры: `mechanic_id` (uuid) или `unassigned=true`,
`status` (повторяемый), `category` (повторяемый `WorkCategory`), `unapproved=true`,
`group` = `mechanic` (по умолч.) | `status` | `car`. Ответ `{items, has_more}`, лимит 200.
Элемент: `id, visit_id, name, status, category, approved_by_client, norm_hours,
assigned_mechanic_id, assigned_mechanic_name, plate_number, make_model, visit_status`.
Группировка = сортировка: `mechanic` — по ФИО механика (без исполнителя — первыми), внутри по
срочности; `status` — по срочности, внутри по машине; `car` — по госномеру, внутри по срочности.

### `GET /vehicles/{id}/work-history` — расширение

Параметр `category` (повторяемый). Элемент += `category`.

## Экраны

Обозначения: веб — чипы (`aria-pressed`) и `<select>`; бот — ряды кнопок, активная с «✓ »,
сортировка/группировка — одна кнопка, переключающая режимы по кругу. Выбор хранится в
args экрана бота (Назад возвращает с тем же фильтром), в вебе — в состоянии экрана.

### Механик

1. **Мои работы**: фильтр Все / В работе / Не начаты / Ждут запчасти / Готовы; режим
   «По срочности» / «По машинам» (во втором — заголовок-госномер над группой).
2. **Выполненные**: период Неделя / Месяц (по умолч.) / Всё; итог Все / Выданы / Отменены;
   шапка «Работ: N · X н/ч»; на карточке дата закрытия.

### Мастер и админ

3. **Заезды в работе**: фильтры Все / Мои / Согласование / Ждут запчасти / Готовы /
   Без механика / Долго стоят; сортировка По дате / Долго стоят / По статусу; админу —
   выбор мастера. На карточке «N дн. в статусе», если ≥ 1 дня.
4. **Доска работ** (новый экран): механик (все / без исполнителя / конкретный), статус,
   категория, «Не согласовано»; группировка По механику / По статусу / По машине. Карточка
   ведёт на экран работы. Вход: веб — кнопка на экране заездов и в «Ещё»; бот — пункт меню.
5. **Архив заездов** (новый экран): период Неделя / Месяц / Квартал / Всё; итог Все / Выданы /
   Отменены; админу — мастер; сортировка По дате / По сумме; шапка «Заездов: N · Выручка: X ₽»;
   «Показать ещё» (веб) / страницы (бот). Вход как у доски.
6. **История работ по авто** (все роли): фильтр по категории.
7. **Работы в карточке заезда**: всегда по срочности (незавершённые сверху), без переключателя.

## Тесты

Сервер — pytest на каждый параметр и сортировку; веб — vitest с MSW (параметры запроса,
чипы, пустые состояния); бот — рендер экранов и кнопок, лимит callback_data 64 байта.

## Вне рамок

Отчёты и графики, фильтры поиска, сохранение выбора между сессиями.
